## 3. 今日改了什麼

**根因**：探索 `site/src/pages/lexicon/[key].astro` 與 `en/lexicon/[key].astro`（Explore agent 確認兩檔邏輯逐字相同，僅 import 路徑差異）發現：全站 5464 個字典頁的 `<title>`／`<meta description>` 全部共用同一句固定敘述（`${headword}｜字典：DPD 逐字文法…`），每頁只有開頭詞頭不同，其餘完全一樣；且完全沒有 `DefinedTerm` JSON-LD 結構化資料（`Base.astro` 已有 `extraSchema` prop 可掛，但字典頁未使用）。這正是「搜尋排名不差、但完全沒人點」最合理的解釋——Google 摘要看不出這頁對應查得到的詞義。

**改動（2 檔，皆在 site/，未動 data/ 內容）**：
- `site/src/pages/lexicon/[key].astro`
- `site/src/pages/en/lexicon/[key].astro`

各自新增：
```
const meaning = entity?.name_zh ?? entry?.gloss ?? '';
const pageTitle = meaning ? `${headword}（${meaning}）｜${t.lexicon.title}` : ...;
const pageDesc  = meaning ? `${headword}，意為「${meaning}」。${t.lexicon.desc}` : ...;
const definedTermSchema = { '@type': 'DefinedTerm', name: headword, description: meaning, inDefinedTermSet: {...} };
```
`meaning` 完全取自既有資料（`entry.gloss`／`entity.name_zh`，DPD/DPPN 既有欄位），未新增/杜撰任何事實，也未動 `data/mn*.json` 或任何白話/研經卡內容。

**驗證**：`pnpm -C site build` 通過（11032 頁，52.7 秒）。抽查 `/lexicon/hutva/`、`/en/lexicon/bhavant/` 產出的 `<title>`／description／JSON-LD 皆正確帶出詞義，不再是通用句。

**上線**：commit `60e2f65`（訊息：「每日 SEO 優化 2026-07-01：字典頁 title/description 改用詞義專屬敘述」）→ push 到 main → 觸發 GitHub Actions → Pages 部署。

**通知 Google 重收錄**：對 strikingDistance 名單對應的 14 個 URL（hutva/bhavant/santika/patipada/cetas/pitimana/bilaso/viraga/panita 中英版）呼叫 `scripts/seo-index-ping.mjs`，14/14 成功。

**預期效果**：Google 摘要下次重新抓取後，這批字詞的搜尋結果會顯示對應詞義（而非千篇一律的通用句），CTR 有機會從 0 開始爬升；因涉及 5464 頁的共用範本，長尾字典頁整體 CTR 都可能受惠，非僅這 14 個 URL。效果要等 Google 重新收錄（通常數天）才看得到，且 GSC 資料本身有 2–3 天延遲。
